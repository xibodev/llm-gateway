Claude Code

For normal use, merge these values into your private settings file and replace the placeholder with a gateway project key.

~/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8787",
    "ANTHROPIC_AUTH_TOKEN": "<GATEWAY_PROJECT_KEY>"
  }
}

On client versions supporting it, CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 in env enables gateway-backed model discovery for the picker. It changes discovery only, not translation, model capability, or account access. There is no implied Sonnet entitlement. Use an exact eligible model when the installed client lacks this toggle.

For a controlled API-key compatibility test:

shell
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787
export ANTHROPIC_API_KEY='<LLMGW_API_KEY>'
claude --bare --model '<MODEL_SELECTOR>'

ANTHROPIC_AUTH_TOKEN supplies bearer auth instead. Claude settings may override process environment, so use per-invocation --settings when necessary.

Codex

~/.codex/config.toml
model_provider = "llmgw"

[model_providers.llmgw]
name = "llm-gateway"
base_url = "http://127.0.0.1:8787/v1"
env_key = "LLMGW_API_KEY"
wire_api = "responses"
requires_openai_auth = false

Set LLMGW_API_KEY in the process. Built-in tools, reasoning summaries, encrypted state, and non-empty include require a native Responses target.

Model selection

Exact provider/model targets one model. An endpoint name runs an ordered chain. A bare provider-native alias is available only when one eligible exact target remains. Response model fields report what served.

If both auth headers are supplied, x-api-key wins; an invalid one is not rescued by a valid bearer token.

Compatibility confidence

Automated fixtures cover discovery, Chat/Responses/Messages envelopes, token counting, streaming terminals, tools, safe metadata, and errors. They do not certify every future installed client release. The real-provider gate also verifies the Claude picker, physical Ctrl+C, Codex Responses, Copilot BYOK, usage attribution, and key revocation.
