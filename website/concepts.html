Request anatomy

Routing without hidden policy.

Every selector resolves to an exact target or an explicit ordered endpoint before provider dispatch.

ConceptsSelectorsFailoverAdaptationGovernanceArchitectureState

llm-gateway is a single-node request router and governance boundary, not a model classifier or quota scheduler.

Model selectors

Exact target

provider/model selects one configured provider and native model. Provider retry can repeat it; cross-target failover does not occur.

Named endpoint

An endpoint is an ordered list of exact targets. Eligible coding requests can advance through the list before output starts.

Bare alias

Provider-native IDs are normalized only when one eligible target remains. Collisions are omitted rather than resolved by order.

config.yaml
endpoints:
  coding:
    failover:
      - { provider: hosted, model: <model-a> }
      - { provider: local, model: <model-b> }

Retries and failover

Retries happen inside one provider target. Endpoint failover moves between targets. Chat and compatible Responses/Messages paths can advance after supported throttling, server errors, or timeouts.

First-byte boundaryAfter streaming output begins, the gateway surfaces later failure instead of replaying partial output through another model.

Embeddings, transcription, speech, image, and video choose the first eligible member. Embeddings intentionally avoid cross-model failover because vector spaces differ.

API adaptation

force_api_support is experimental and off by default. The persisted model catalog can direct Chat to a Responses-only target. Translation is catalog-driven and rejects fields it cannot preserve; it is not a universal intermediate representation.

Governance path

  1. Authenticate the static or project key.
  2. Resolve principal, project, role, key status, and expiry.
  3. Intersect project/key model and provider allowlists.
  4. Consume request-count quota.
  5. Resolve exact target or endpoint.
  6. Resolve private/system/shared credential under provider-specific rules.
  7. Dispatch, record usage and telemetry, reconcile token/cost/credit counters, and evaluate alerts.

When policy or credentials remove every target, resolution fails closed.

Architecture

request flow
Claude / Codex / Copilot / SDK / HTTP
                │
     OpenAI or Anthropic facade
                │
 authentication + project/key policy
                │
 exact target / endpoint / safe alias
                │
 provider retry + ordered failover
                │
 transport + credential adapter
                │
 hosted API / subscription / local model

The embedded Preact console calls authenticated admin/user APIs. SQLite owns IAM, keys, usage, quotas, audit, alerts, and outbox. Catalog, failover telemetry, optional request logs, and the legacy savings ledger remain local sidecars.

Single-node state

SQLite WAL and one deterministic control-plane connection simplify quota and lifecycle transactions. There is no clustered state, distributed circuit breaker, or HA scheduler. Use backup and restore for continuity.
