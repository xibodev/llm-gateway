Addressing

Exact when you need control. Resilient when you need continuity.

A model selector has one explicit meaning. No weighted scheduler, hidden classifier, or fabricated quota signal decides for you.

provider/model

Send a request to one exact configured provider and native model ID. Provider retry policy may retry that target, but the gateway does not move it to another model.

Deterministic aliasesBare provider-native names are accepted only when they identify one unambiguous, policy-eligible exact target.

endpoint

Give an ordered list of pinned targets a stable name. Eligible Chat, Responses fallback, and adapted Messages requests can advance before output starts.

Failover is surface-specificStreaming stops moving after the first byte. Embeddings, audio, image, and video choose one eligible target.

Authenticated quickstart

Install the image. Configure your route.

No clone or build required. Put this compose.yaml in your own private installation folder and generate its .env once. Then run docker compose up -d and open http://127.0.0.1:8787/console. Keep the folder, keys and state volume for restarts and upgrades.

  1. Create a human owner and project.
  2. Connect and verify one provider.
  3. Create an ordered endpoint.
  4. Mint a project key for your CLI.

Follow the complete quickstart →

compose.yaml · published image
services:
  gateway:
    image: ghcr.io/xibodev/llm-gateway:0.3.1
    ports:
      - "127.0.0.1:${LLMGW_PORT:-8787}:8787"
    environment:
      LLMGW_API_KEY: ${LLMGW_API_KEY:?set LLMGW_API_KEY in .env}
      LLMGW_CREDENTIAL_ENCRYPTION_KEY: ${LLMGW_CREDENTIAL_ENCRYPTION_KEY:?set LLMGW_CREDENTIAL_ENCRYPTION_KEY in .env}
    volumes:
      - state:/state
    restart: unless-stopped

Request-path governance

Identity and limits stay attached to every call.

Humans, services, projects, memberships, and keys resolve before routing. Project and key policy intersect; an empty eligible target set fails closed.

  • Model and provider allowlists
  • RPM and daily/monthly request limits
  • Daily input/output and monthly total tokens
  • Estimated cost and model-credit budgets
  • Persistent usage attribution and retained audit history

Explicit boundaries

Complex where correctness needs it. Deliberately small everywhere else.

  • Single-node SQLite, not clustered HA.
  • Core protocol compatibility, not every vendor API field.
  • Ordered failover, not quota-aware or weighted scheduling.
  • Operator-triggered local backups, not a remote backup service.
  • Trusted reverse-proxy SSO, not an embedded identity provider.
  • Private/LAN provider URLs allowed; SSRF blocking intentionally absent.
